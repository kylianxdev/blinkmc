USE CASES

Most servers are empty most of the time

A Minecraft server only has to run while someone is playing. The rest of the day it keeps gigabytes of RAM and ticks an empty world for nobody. Blink puts it to sleep in those hours and wakes it the moment a player joins: nobody notices, and the memory and CPU are free for everything else.

GREENER

Even if your VPS has the RAM anyway

A sleeping server is not only cheaper. An empty Paper server still ticks 20 times a second, all day: we measured about 3 % of a CPU core for an empty world. Frozen, it uses nothing. And the bigger win is for hosts: servers are packed onto machines by RAM, and a server asleep for 10 minutes needs 7 MB instead of 3 GB, so the same players need far fewer machines running day and night.

The math, so you can check it

  • A machine: 64 GB of RAM, 56 GB usable for servers, about 150 W day and night
  • With Blink, the RAM you need is twice the average awake share (for evenings when everyone plays), plus 7 MB per sleeping server
  • Every machine that doesn't have to run saves about 1,300 kWh a year
  • 0.25 kg CO₂ per kWh, about the European grid average

An estimate, not a promise: real hosts differ in machines, power and how players spread over the day. The one thing we measured ourselves: 3 GB to 7 MB per sleeping server, and 3 % of a core to 0.

HOW IT WORKS

Three states, one port

Blink, one small program, owns the public port. The server list, the MOTD and the icon always answer, and a join is let through as soon as the server is there.

WHAT MAKES IT FAST

Freeze, don't stop

1

Freeze instead of stop

A paused JVM keeps all its state, so waking it is instant. Blink saves first and moves the paused server's memory out of RAM: compressed at first (back in under a second), to disk after 10 minutes: 7 MB instead of 3 GB.

2

Paper without paperclip

Paper's launcher loads the server in its own class loader, which Java's AOT cache can't store. Blink starts the server directly.

3

Java's AOT cache

On Java 25 Minecraft's method type table is too big for the cache; Java 26's streamable AOT objects make the full cache fit. 13 s becomes 4 s.

4

One tiny program

1.5 MB of RAM instead of 5.7 MB, one static file, about 1 GB/s of player traffic on one thread.

INSTALL

Get started

One command. Stop your server, make a backup, go to its folder (paper.jar, a Fabric or vanilla jar, or Forge's run script) and paste this:

Linux Linux / macOS, no root Windows 
curl -fsSL https://raw.githubusercontent.com/kylianxdev/blinkmc/main/install.sh | sudo bash
Copy

Full install: a service, plus swap and zswap so a sleeping server leaves RAM. Needs root.

Players join on the same address as always. Your world stays as it is; Blink moves the server to a port of its own and raises Paper's watchdog (everything it changes), and blink restore or --uninstall puts it back. Read the installer first? install.sh, install.ps1. Networks: a Blink per backend server, see the README.

FAQ

Questions

Do players need to install anything?

No. It is a normal Minecraft server for them. The only thing they may notice is a different MOTD while the server sleeps.

Does it work with BungeeCord or Velocity?

Yes: a Blink in front of each backend server. Tested with one proxy, a lobby and four personal worlds, with bots that log in and switch: 0.3 to 1.7 s to a sleeping world (about 3 s on the first visit after a server restart), and five sleeping servers use about 1 GB together.

Is a frozen server safe for my world?

Blink saves the world (save-all flush) before every freeze and checks that nobody joined meanwhile. Stopping it thaws the server first and lets it save and shut down normally. Nothing in your world is changed. Still: try it with a fresh backup first.

What does Blink change, and how do I undo it?

The server's port in server.properties (Blink takes yours, the server moves behind it), Paper's watchdog and its PROXY protocol setting, and on Linux with the full install a service, swap and zswap. blink restore puts back only what Blink set, --uninstall removes the rest. The full list.

Do I need Java 26?

No. Your server needs the Java its Minecraft version needs. Java 26 makes a cold start of Paper fast (4 s instead of 13, with Java's AOT cache); waking a frozen server is just as fast on any Java.

Do I need a whitelist?

No. Without one anyone can wake the server, also new players; a bot that does only keeps it awake until the next freeze. With the whitelist on, only whitelisted players can wake it.

Does it need root or change my system?

Only the full Linux install: a service, a swap file and zswap. The portable install (Linux, macOS) and the Windows install change nothing outside your server folder.

Does it work with my hosting provider?

Blink runs next to your server, so you need a machine where you can run your own programs: a VPS, a dedicated server or your own PC. Most shared Minecraft hosting plans don't allow that.

Does Blink send anything?

Once a day it downloads a 1 byte file from Blink's GitHub releases; GitHub counts the downloads. Nothing is sent. Off with usage_stats = false or DO_NOT_TRACK=1.

Spigot, Fabric or Forge?

Yes. blink init and the installers recognise Paper, Purpur, Fabric, Quilt, Forge, NeoForge and vanilla, and sleeping works the same for all of them. The fast cold start (Java's AOT cache) is for Paper and its forks; real player IPs need a PROXY protocol mod on Fabric and Forge.
