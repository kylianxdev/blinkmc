HOW IT WORKS

Three states, one port

Blink, one small program (1.5 MB of RAM), owns the public port. Players never notice it: the server list, the MOTD and the icon always answer, and a join is simply let through as soon as the server is there.

AWAKE

Playing

A normal Paper server. Blink only passes on the connection, with the players' real IPs. When everyone left, the heap shrinks and the world stops ticking.

same TPS, same plugins
FROZEN

Asleep

30 seconds after the last player leaves, the server saves and the JVM is paused, not stopped. Linux squeezes its memory into compressed RAM (zswap) and the coldest part to disk. On a join it simply continues.

wake up: 0.1 s
COLD

Off

After a reboot or an update the server starts from scratch. Paper starts directly with Java's AOT cache, so even that only takes a few seconds.

cold start: 4.4 s

WHAT MADE IT FAST

Five tricks

Freeze instead of stop

A paused JVM keeps all its state, so waking it up is instant. Blink first lets the heap shrink, then pushes the paused server's memory into zswap (zstd) and swap: 0.19 GB instead of 3 GB. Paper's watchdog is told not to panic about the time it was asleep.

Start Paper without paperclip

Paper's launcher loads the server in its own class loader, which Java's AOT cache cannot store. Blink reads the class path from paper.jar and starts org.bukkit.craftbukkit.Main directly.

Java's AOT cache with streamable objects

A training run records what Paper loads, links and runs. On Java 25 Minecraft's method type table is too big for the cache. Java 26's streamable AOT objects make the full 230 MB cache fit.

One tiny program

Blink is built on lazymc, fixed for current Paper and rebuilt to be small: 1.5 MB of RAM instead of 5.7 MB, 2 threads instead of 10, one static 1.6 MB file. It saves the world before every freeze, moves the frozen server's memory out of RAM itself, and still passes about 1 GB/s of player traffic on one thread.

Deep sleep

After a day frozen, Blink stops the server completely. Then only Blink's 1.5 MB is left, and the next join is a 4.4 s cold start.

INSTALL

Get started

One command. Stop your server, go to the folder with your paper.jar and paste this:

curl -fsSL https://raw.githubusercontent.com/kylianxdev/blinkmc/main/install.sh | sudo bash

Full install: a systemd service, plus swap and zswap so a frozen server leaves RAM. Needs root.

It sets everything up

Blink, and Java 26 if you don't have it (Linux). Your MOTD and version are read from your server. Your world and settings stay as they are, and --uninstall undoes it all.

Play

Players join on the same address as always. 30 seconds after the last player leaves, the server saves and freezes. The next join wakes it up.

Tweak it (optional)

# options go after "bash -s --"
curl -fsSL https://raw.githubusercontent.com/kylianxdev/blinkmc/main/install.sh | sudo bash -s -- --heap 6G --sleep 120

Linux, macOS and Windows, with Paper or a Paper fork. Every change is tested on all three with a real server. All options are in the README.

FAQ

Questions

Do players need to install anything?

No. It is a normal Minecraft server for them. The only thing they may notice is a different MOTD while the server sleeps.

Do I need a whitelist?

No. Without a whitelist anyone can wake the server, also new players. A bot that wakes it only keeps it awake until the next freeze, 30 seconds later. With the whitelist on, only whitelisted players can wake it. Want to keep bots out without a whitelist? Set wake_known_players = true: then only players who joined before can.

Does it work with BungeeCord or Velocity?

Yes: put a Blink in front of each backend server and point the proxy at Blink's ports. Tested with one proxy, a lobby and four personal worlds, with bots that log in and switch: a switch to a sleeping world takes 0.3 to 1.7 s until you are in it (about 3 s on the first visit after a server restart), and all five servers frozen use about 1 GB together. Setup in the README.

Does it work for big servers?

Yes. One thread passes about 1 GB/s of player traffic, enough for well over a thousand players; --threads 4 doubles that for 56 kB of extra memory. A big server is rarely empty, so it simply stays awake.

Is a frozen server safe for my world?

Blink makes Paper save the world right before it freezes, and checks that nobody joined meanwhile. Stopping it thaws the server first and lets Paper save and shut down normally. Nothing in Paper or your world is changed. Still: try it with a fresh backup first, like any tool that runs your server.

Does it need root or change my system?

Only the full Linux install: it adds a service, a swap file and zswap, so a frozen server's memory can leave RAM. The portable install (Linux, macOS) and the Windows install change nothing outside your server folder.

Does Blink send anything?

Once a day it downloads a 1 byte file from Blink's GitHub releases; GitHub counts the downloads, which is how we know how many servers use Blink. Nothing is sent. Turn it off with usage_stats = false or DO_NOT_TRACK=1.

What about plugins, dynmap or BlueMap?

Plugins freeze and wake with the server. BlueMap's web server can run on its own, so the web map stays online while the server sleeps. The write-up shows how.

Can I undo it?

Yes: run the same command with bash -s -- --uninstall (or delete blink and blink.toml after a portable install). Your own server.properties comes back.

Does it work with Spigot, Fabric or Forge?

The sleeping part works with any Java server: set command in blink.toml. The fast cold start is written for Paper and its forks (Purpur, Folia, Leaf), because it reads Paper's launcher lists.
